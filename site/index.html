A personal operating system, in a folder of plaintext.

opskit turns Markdown files in your own git repo into a system that runs your knowledge, tasks, and work — drivable by you, by schedules, and by AI agents, all through one ops command. No server, no cloud, no lock-in: you can grep your notes or walk away at any time.

curl -fsSL https://raw.githubusercontent.com/gabros20/opskit/main/script/get -o get.sh && sh get.sh

macOS / Linux · Python 3.10+ + git · zero required deps · MIT. Verify the published hash before running — the README shows the ritual.

Two faces. One door.

Humans get ops ui — menus and forms generated from the machine contract, nothing to memorize. Agents and scripts get ops <verb> --json — one frozen envelope and a strict exit-code protocol. Both enter the same dispatcher, so the guardrail and the logs see every action identically. The UI is not a second implementation: it reads the contract and generates itself, so a new verb appears in the menus the moment it exists.

Four roots. Separated on purpose.

Siblings sit next to ~/ops, never inside it. The knowledge repo stays small, plaintext, and fast — and the safety wall is rooted in this layout. Inside ~/ops, everything is a Markdown file; indexes and embeddings are disposable caches rebuilt from the text.

The daily rhythm is five verbs.

start → capture / triage / task → close, with week on Fridays. You never memorize paths or formats — the verb owns placement; you provide the content. Everything else is discoverable through ops help, tab-completion fed by your actual note slugs and task IDs, or the guided UI.

a day in the vault
$ ops start                             # morning: today's journal, carry-forward, dashboard
$ ops capture "RRF beats naive hybrid"  # a thought → inbox/ (zero decisions)
$ ops triage                            # proposes: wiki note? task? — you approve
$ ops search "ranking fusion"           # ranked file#heading hits with snippets
$ ops open rrf                          # one resolver: task id → note slug → asset → search
$ ops close                             # evening: summarize the day, flag loose ends

The verb list is generated, not maintained — ops.json describes the whole surface, and every new verb (or installed plugin) appears in help, completion, the UI, and MCP automatically.

Every call passes the same wall.

Before any verb runs, the guardrail classifies it — yours, a cron job's, a plugin's, or an agent's. New and untrusted verbs default to confirm. It's all git underneath, so even a mistaken write is one git revert away.

ClassMeaning
readpure read — runs freely, even unattended
safe_writewrites inside the roots — every change is a revertible git diff
draft_onlyproduces a draft (e.g. invoice) — the system never transmits
confirmneeds an explicit --yes — exit 3 with the exact re-run when missing
denyalways refused: force-push, rm -rf, secrets, paths outside the wall

--dry-run on any mutating verb prints what would happen and writes nothing — it counts as a read, so even confirm-class verbs are explorable without --yes.

Any agent. Same door, same wall.

Point any capable agent at ~/ops and it drives the same system. It reads AGENTS.md (the open contract standard) and the operate-ops skill; it parses the generated ops.json — every verb's args, schemas, risk class, per-action grammar, completion providers; and for MCP hosts, ops mcp is a stateless stdio server whose tool list is generated from the same contract. An agent never gets more power than you do.

ops.json — one verb, trimmed
{"verb":"task", "risk":"safe_write", "group":"TASKS",
 "dry_run":true,
 "actions":[
   {"name":"add",  "args":[{"name":"title","required":true}]},
   {"name":"move", "args":[
     {"name":"id","complete":"task-id"},
     {"name":"status","enum":["inbox","active","waiting","done"]}]},
   {"name":"done", "args":[{"name":"id","complete":"task-id"}]}]}

Artifacts in. Honest knowledge out.

PDFs, recordings, screenshots, and URLs become searchable, linked, provenance-labeled notes. Extraction is tiered and local — each format tries the best locally available tool and degrades gracefully. A model may propose, rank, or label; it may never directly write "truth" into your vault.

the pipeline
$ ops files ingest talk.pdf --research --extract  # file it + extract text → a DERIVED note
$ ops files distill talk                          # compile concept notes (drafts) from the extract
$ ops organize                                    # scan for links/dupes/fixes → proposals, zero LLM writes
$ ops organize review                             # page through each proposed op with its exact diff
$ ops organize apply --yes                        # replay ONLY what you approved — one git commit per op
human

Notes you wrote. The default author; what search trusts most.

derived

Machine extractions — labeled with derived_from, source_sha256, and the tool that made them.

agent

Model-written drafts — gated as status: draft until you promote them in triage. Machine material can never quietly become truth.

Three local search stages find it all again: keyword + wikilink graph out of the box; local vectors and reranking opt-in. The index is disposable — rm -rf .index && ops index rebuilds it from the text.

Template to vault in five minutes.

The repo is a template, not your data. The installer clones your own copy to ~/ops, wires the machine, and never pushes anywhere. Needs macOS or Linux, git, Python 3.10+ — nothing else is required.

quickstart session
$curl -fsSL https://raw.githubusercontent.com/gabros20/opskit/main/script/get -o get.sh $shasum -a 256 get.sh # compare against script/get.sh.sha256 — read it, then run it $sh get.sh # lean vault at ~/ops, non-interactive, no sudo $ops setup --wizard # guided first-run: skeleton + terminal UI on, heavy layers off $ops ui # point-and-pick from here

Kick the tyres first: sh get.sh --demo installs a throwaway vault with example notes into a tmp dir — one rm -rf removes it completely. Semantic search, local models, backups, and scheduled jobs are opt-in layers: ops setup is the dashboard, ops setup <layer> --yes advances one, --dry-run previews anything.

Engine updates flow. Your notes never move.

./script/update 3-way-merges only the engine files: unmodified files fast-forward, your local engine patches merge, conflicts get markers, and your wiki, tasks, and journal are never touched. The terminal UI updates the same way — the engine ships the version it expects, and the setup dashboard tells you when a newer binary is pinned and ready.

ops setup — the layer dashboard

  ◐ ui          Terminal UI             partial  optional  update available: 0.1.1 → 0.1.2

The ui layer downloads a self-contained compiled binary (sha256-verified, pinned to the release the engine was tested with) into the vault's own .local/bin/ — no Node on your machine, no node_modules in your vault, ever.

The principles it enforces: plaintext is the truth; git is the spine; one door (ops <verb> is the only writer); agents are guests behind the same guardrail; nothing transmits without a human; reversible, zero-install, no server.

Named non-features, so they don't creep in: no server, no daemon, no cloud sync, no proprietary format, no auto-send. The vault plus git history is the whole platform.
